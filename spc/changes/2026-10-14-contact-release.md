# 联系人界面简化与整合发布

来源：用户验收截图，明确要求国内／海外同步修改并将本任务此前改动发布上线。主责为通讯录／个人资产，负责人及联合评审人待认领；关联账号／工作区与连接器模块。

## 规则与范围

- CONTACT-FILTER-01：移除搜索、主体类型、客户来源、所属成员、创建开始日期、创建结束日期、排序控件上方的可见文字。保留控件、选项、占位、aria-label、组合筛选与重置功能。
- CONTACT-FORM-02：移除手动添加联系人中的手机号、邮箱核实勾选项及文字，不将普通手动输入自动标记为已核实；因此仅同邮箱的手动记录不再通过该勾选动作合并到 CRM 联系人。手机示例导入的既有来源与幂等处理不变。
- 同批发布 CONTACT-ADD-01 与 CONTACT-CARD-01：添加弹窗只保留手动／手机；卡片隐藏“示例客户”，右下角显示创建时间，右上角显示有权限的共享按钮。

复用 ContactsPage、ContactDialog、Select、ContactTag 及现有模块 CSS，两地个人／团队共用工程，主题差异保持。无新增组件、存储键、数据迁移或架构例外；不涉及独立企业域。ContactsPage 超过 500 行，本次限于现有列表 JSX 展示，未扩展职责。上游为当前工作区、既有联系人与输入，下游为既有筛选、保存及权限模型。MARKET-01、SPACE-01、ACCESS-01、SHARE-01、EXPIRE-01 保持，遵守 FE-01～FE-10。旧核实勾选验收按 CONTACT-FORM-02 改为验证记录独立，CRM 优先规则仍由模型用例覆盖。

## 验收与发布

Given 两地个人／团队，When 筛选、重置、打开添加弹窗和保存，Then 不出现截图圈定内容，控件仍可操作、手动创建有效、手机导入幂等。失败保留输入、取消不写入、只读与无权限沿用现有流程，未新增异步或目录空状态。覆盖 390／768／1080／1440px，核对卡片位置和共享操作。

验证：`npm run check`、`npm run build`、受影响联系人用例及 `PLAYWRIGHT_CHANNEL=chrome npm run test:release`。发布使用现有 Pages workflow 的市场发布验收路径（`skip_browser_acceptance=true` 实际执行 `test:release`，不是跳过测试），发布后核对两地线上界面与资源。
