## 需求、设计与实施计划

用户确认：所有场景 Agent 消耗来自 AgentPlatform 实际 token，设计积分充足、不足及边界交互，覆盖国内／海外 × 个人／团队，并同步集中 PRD。

1. 业务／契约：统一用量回执、费率计算、幂等结算与待结算记录；删除按字符／字节长度推算费用的路径。接口未接入时使用明确标注的固定模拟回执，正式回执缺失不估算扣费。
2. 混合组件：保留首页、闪念、日程待办、联系人、录音、会议及历史会话的原有内容／人工确认流程，在对话输入区域附近复用 AgentCredits。已有输入和回答不得因不足丢失；普通保存确认不额外调用 Agent／扣费。
3. 展示组件：紧凑余额栏显示个人／团队池、可用余额及最近用量；details 展开输入／输出 token、来源、费率版本、结算状态。沿用市场语义变量、Button／Select 和可访问状态文本。
4. 评审工具：仅 review=1 在对话框内提供“计费状态预演”；独立内存余额与样例问题，模拟发送、停止、充值恢复、回执补齐和重复回执。明确标记预演，不写用户余额、历史或奖励；普通输入框继续真实本地原型流程。两套模式不能混淆。
5. 验证：模型覆盖回执错误／缺失、零用量、精度、幂等、余额恰好／不足；浏览器覆盖两地两类工作区、团队角色与所有场景，检查 390／768／1080／1440 宽度。

## 规则与边界

AGENT-CREDITS-01：扣费唯一事实是平台返回的实际 token 用量；输入上下文、输出、多步骤累计由平台统计，客户端不重复累加。回执至少包含 runId、来源、模型、费率版本、inputTokens、outputTokens、final。正式接口字段映射与缓存／推理 token 口径待 AgentPlatform 确认；本地字段是应用内适配契约。

AGENT-CREDITS-02：请求锁定市场、工作区、用户及 runId。每轮只结算一次；缺失／非法／非最终回执进入待核对，不显示“免费”或虚构精确进度；确定零用量可结算为 0。重复回执不重复扣费，不接受同一 runId 的冲突回执。

AGENT-CREDITS-03：发起前检查权限、有效权益、余额及未完成结算。余额为 0 阻止新请求。结束按回执结算；余额恰好耗尽可完成本轮；超出余额保留回答和待结算记录，不透支、不扣其他池，不自动再生成。充值后只重试结算已有回执。

AGENT-CREDITS-04：普通保存／人工确认没有新 Agent 调用时不再收费。停止／失败不等于免费，已发生用量需最终回执，未收到时待核对。Team 到期暂停新 AI，历史保留；到账不会自动恢复到期权益。

现有两地费率继续为演示配置，不作为正式商业报价。国内 grant 有效期／先到期先消耗继续生效，海外余额规则保持独立。生产权限、计量、锁额、并发事务及验签需要服务端实现，本地存储不能替代。
