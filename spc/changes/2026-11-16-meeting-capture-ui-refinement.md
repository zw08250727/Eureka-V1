## 组件与影响

- `MeetingPage` 去掉冗余页头与搜索，保留详情资料库；信息区首行参会人、客户名称、商机项目并排且自适应换行，标签与图片在展开区。保留现有参与人／元数据对话框、图片上传／移除、只读约束和保存。现有大文件仅调整布局，未扩展数据职责。
- 复用 `DomesticAudioPlayer`、`MeetingVideoPlayer`、`RecordingLauncher`、`Select`、`ReferenceDialog`；新增纯 UI `MediaSkipIcon`，统一播放器前后 15 秒细线 SVG。
- `RecordingModeIcon` 使用统一 1.5px 笔画，标题 48px 容器内保持 24px 图形；列表、详情、资料库共用，硬件沿用已有图标资产。

- 录制对话框统一为复杂弹窗 720px、两列模式／内容选择、三列窗口缩略图、语义按钮圆角和主题主按钮；小屏单列、44px 触控。国内黑色主按钮，海外使用品牌主按钮，市场差异仅由主题变量提供。
- 上游录制设置、会议来源与权限沿用；下游列表、详情显示改变。存储、权限、转写／总结、Agent 状态逻辑未改。无新增设计变量、检查例外、数据迁移或历史原型修改。
- 线上复核和公开资源证据见 `docs/baizhi-meeting-reference.md` 本日条目。未复制私有数据。

### 用户追加调整：移除弹窗转写语言

国内和海外的录制会议弹窗移除「转写语言」字段。开始录制时沿用既有默认中文（普通话），录制中页面的语言控件保留；capture 元数据结构及历史记录不迁移。回归同时确认弹窗不存在该下拉框、开始录制后默认语言正确。追加修改后 `npm run check`、`npm run build` 与 `git diff --check` 通过；`meeting-capture.spec.ts` 两地 14 项通过，设置截图已刷新。

本轮交付本地组件与路由更新，未发布；真实屏幕和声音采集保持已确认的模拟范围。

### 用户追加调整：与历史图标严格对齐

此前新图形使用 24px viewBox 并铺满图形区域，历史麦克风／耳朵资产使用 32px 画布、7px 内边距和 18px 内图形坐标；相同 CSS 尺寸和 stroke 数字下，新图形的实际笔画更粗且占比更大。因此只降低 stroke 或把标题图形限制为 24px 仍不能与历史样式一致。

本轮保留历史 `recording-mic-source.svg`／`recording-ear-source.svg`，APP、Web、视频、上传四个新 SVG 沿用同一 32px 画布、7px 偏移、1.5px 圆角笔画、颜色和底板；音频直接复用历史麦克风。`RecordingSourceGlyph` 与 `RecordingModeIcon` 共用这些矢量资产，列表、标题、录制模式和范围选择同步；详情标题恢复按 48px 画布等比显示，实际图形与历史资产比例一致。原数据、五类来源标识和录音模式语义均不改，两市场／个人／团队共用。无新增例外、变量、存储变动或冻结文件修改。负责人及规则沿用本记录，待人工评审状态不变。

验收：同一列表内 Web／硬件、视频／硬件的笔画、底板和留白一致；标题保持同一缩放比例；两地录制弹窗同组图标一致，所有 SVG 资源加载成功。`npm run check`、`npm run build`、`git diff --check` 均通过；meeting-capture、ui-density-source、thought-lifecycle 两地相关回归共 32 项通过。已用隔离浏览器中的五类来源样例并排核对，两地均为 24px 列表图块、32px 原始画布，资源全部解码成功；对照截图 `test-results/meeting-icons/{cn,global}-list.png`，详情及弹窗截图随回归刷新。
