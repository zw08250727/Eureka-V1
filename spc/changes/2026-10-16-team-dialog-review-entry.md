# 创建团队自适应弹窗与悬浮评审入口

日期：2026-10-16。来源：用户截图及本轮明确修改要求。适用国内／海外、个人／团队的评审入口与创建团队套餐介绍。

## 目标与职责

原市场通用样式将双栏套餐弹窗覆盖为520px宽，导致文案碎行、内容过高。团队套餐介绍恢复最大980px、随视口缩放，760px及以下单栏；最大高度受可视区约束，内容内部滚动、头部关闭按钮常驻。账户菜单和移动导航的评审工具入口移到右下角，44px点击高度、响应安全区，普通市场流程仍默认不显示。

规则：UI-TEAM-DIALOG-01、UI-REVIEW-01；保持 MARKET-01、ACCOUNT-01、RIGHTS-01、ASYNC-01，不改计价、创建资格、订单与任何存储数据。国内黑灰／海外靛蓝颜色继续使用语义主题。

UI主责：张伟；关联订阅：唐娅（国内）、鹤飞（海外）；账号／工作区主责待认领。本记录不代表负责人已签署验收。用户已要求执行此次UI调整；尚未要求发布本次修改。

## 实现与依赖

复用 ManagementDialog 的原生dialog／关闭与焦点管理、现有团队套餐内容、ReferenceDialog、RefIcon及评审视角控件。套餐样式仅限含ws-plan-intro的弹窗，不扩展所有标准表单宽度；不编辑生成prototype.css或冻结源。悬浮按钮由ReferenceShell统一渲染，替代两处菜单入口，层级低于原生模态浮层。同步公共UI规范与PRD团队创建／状态章节。

## 验证

- `npm run check`、`npm run build`通过。
- Chrome两地各验证390×844、768×1024、1080×680、1440×900、1920×1080、844×390，共12组：弹窗在视口内，无横向溢出，手机单栏、桌面双栏、短屏内部滚动；滚动到创建按钮时关闭按钮仍可见。
- 每组都走过套餐→团队名称→确认订单，并从悬浮评审工具重新体验；原有校验和草稿流程继续使用。未操作真实支付服务。
- 普通市场路由没有评审按钮；review=1只出现一个固定右下角入口，Esc关闭评审面板后焦点返回触发按钮；两地无页面脚本错误。
- 截图核对使用禁用过渡动画的稳定截图，覆盖两地桌面、手机及右下角入口；证据在`/tmp/eureka-*-team-dialog-*.png`和`/tmp/eureka-*-review-floating.png`，浏览器验证日志`/tmp/eureka-team-dialog-verify.log`。

原有资格、加载、支付失败、过期、存储冲突和数据恢复逻辑未修改；本轮只验证受影响的呈现与入口行为，不宣称重新验收全部账务模型。

回滚：撤回shell评审入口、ui-polish中的悬浮样式、team-pricing中自适应样式及对应规范／PRD片段；保留此前PRD拆分与模块分工更新。不清理用户浏览器数据。
