## 问题、范围与规则

用户要求悬浮评审按钮可任意拖动；余额与预演配置收进工具；模拟必须融合原推荐问题、输入框、发送按钮和消息流；统一 Credits；隐藏输入／输出 token 数，在生成中自动轮换轻量文案。

适用国内／海外 × 个人／团队，覆盖首页、闪念、日历、联系人、会议、录音及历史会话。规则版本 rules-20261018-04，新增 AGENT-CREDITS-05。01～04 的实际回执、归属、精度、幂等、权限和恢复口径不变；国内有效期／批次与海外累计余额差异不变。前一轮变更单中的常驻余额栏、展开 token 明细与独立预演区域由本轮替代。

## 最终组件与操作

- ReviewFloatingButton：鼠标／触控拖动，5px 阈值区分点击；边界保留8px，缩窗夹限，方向键移动，marketStorage 按市场记住位置。默认位于右侧中部，避开发送／停止区域，用户选择的位置优先。
- CreditReviewProvider／AgentCreditPreview：工具仅配置场景、应用、模拟到账／续费／最终回执到达、结束模拟。显示真实余额与独立模拟余额，不提供第二个问题输入框或模拟发送按钮。需要先打开当前 Agent；应用场景后关闭工具，不自动发送。
- useAgentCreditSimulation：连接各场景的原发送函数；使用原推荐问题、输入框、Enter 和原发送按钮。模拟在进入真实网关与账本之前拦截，不写历史、任务奖励或用户余额。
- AgentSendButton：原位置、原样式和原快捷键；模拟生成中切换为停止按钮，完成／停止后恢复发送。真实流程继续调用原场景处理函数。
- AgentSimulationMessages：只生成原样式的用户／Agent 消息行，插入现有消息滚动容器，没有卡片、独立面板、单独滚动区或常驻余额。回答逐段输出，Credits 放在对应回答末尾，多轮模拟消息保留。
- AgentCredits：真实计费反馈也移入现有消息流。打开默认无反馈；旧待结算记录在再次尝试发送时恢复处理入口，充值后只结算原运行。用户 UI 隐藏输入／输出 token 数及换算信息。
- demo-stream／AgentWaiting：本地类型化文本增量与 thinking／skill／mcp／writing 过程；按问题组织行动清单、复盘、需求分析。80ms文本增量、6.4秒完成，中断样例3.2秒；过程内1.2秒换趣味文案，约29秒长等待提醒。只在当前输出文字下方出现一处状态行，纯文本无工具事件。减少动态效果停用呼吸与光标动画，读屏只播阶段名；计量独立于播放，时长非生产承诺。
- 账户、订阅、充值、奖励及提示统一 Credits；旧系统流水标签在展示时转换，不迁移旧数据，历史更新日志保留原文。

配置场景不产生消息。零余额／团队到期时保留原输入；结算不足时保留回答，显示原运行待结算费用；停止保留当前部分回答；失败保留输入。到账只补模拟池，由原回答中的重新结算按钮完成本轮。成员使用“联系管理员”并在工具模拟管理员到账；到期团队通过模拟续费恢复。回执到达更新原回答末尾，不重新生成。

新建会话清除模拟消息与余额快照，保留应用场景。结束模拟恢复普通发送。切页／切空间／切身份销毁快照与计时器。普通模式无配置且不拦截发送。基础 UI 不引入业务依赖，新增业务组件复用语义变量、Button／Select。

## 验收路径

`/cn/workbench/?review=1`、`/global/workbench/?review=1`；团队加 `space=team-eureka`，成员加 `actor=kevin`。先打开 Agent，再进入评审工具选择场景并应用，回原输入框操作。

1. Given 只打开 Agent 或仅应用场景，Then 不新增消息、默认余额或计费区域。
2. Given 已应用场景，When 从原推荐问题／输入框发送，Then 用户问题与回答进入原消息列表，原按钮变为停止；多轮、停止、失败、空余额及恢复均不写真实账本。
3. Given 生成中，When 当前过程1.2秒过去／完成／停止，Then 文案轮换／停止，无 token 数或换算信息；手机输入及停止可达。
4. Given 悬浮按钮，When 拖动、键盘移动、刷新、缩窗，Then 位置记忆且可见，拖动不误开工具。
5. Given 待结算运行与刷新，When 再次发送、补足并重结算，Then 保留问题与回答、只结算原运行，不跨池。
6. Given 国内账户／奖励／订阅／充值，When 查看与操作，Then 统一 Credits，原有效期、权限、领取次数与账务模型不变。
