# 日程、待办详情间距

来源：用户反馈两类详情内容过于分散，要求收紧间距。主责为日程／个人资产模块，负责人及联合评审人待认领；适用国内／海外、个人／团队。

## UI-CALENDAR-07

复用 CalendarPage 的详情结构和既有控件，仅在市场样式兼容层限定 `#personal-actions` 的详情区域：卡片内边距 26→16px，主栏模块间距 20→12px，主栏与来源栏间距 24→16px，字段行上下留白 19→8px；首末字段不重复叠加外侧留白。字段标签与值间距 24→16px；标题与内容、备注、关联会议、来源说明同步收紧。保留文字大小、可读换行、按钮点击区域与现有响应式单栏。顶部返回及操作区域与内容间距收至 16px，不影响日历列表或编辑表单。

没有新增组件、依赖、存储或业务逻辑；不改冻结原型和生成 CSS，遵守 FE-01～FE-10。上游仍为原记录，下游编辑、提醒、备注、关联会议、录音及完成状态流程不变；MARKET-01、SPACE-01、ACCESS-01、SHARE-01、EXPIRE-01 保持。加载、空内容、失败、只读、禁用、恢复与原流程一致，无迁移或资料删除。

## 验收与回滚

入口：两地 `/workbench/?view=calendar`，个人或团队中打开任一日程／待办。Given 已有记录，When 查看详情并打开备注、提醒、关联会议，Then 内容紧凑、字段完整、控件可用，待办完成／重新打开保持可用。覆盖 390／768／1080／1440px、个人捕获来源与团队手动来源。

`npm run check`、`npm run build` 及 UI-DENSITY-04／05 两地 4 项回归通过。Chrome 补充验收两地个人／团队的日程和待办详情，在 390／768／1080／1440px 下内容无横向溢出、按钮保持桌面至少 36px／移动 44px，备注弹窗、提醒编辑、关联会议及待办完成／恢复操作通过，浏览器无脚本错误。截图核对两地桌面与窄屏；桌面日程安排卡约 256px、待办安排卡约 168px。本地交付，人工验收待用户；未发布。回滚本规则对应的局部样式即可，无数据回滚。
