# UI 规范

版本：1.2 / 2026-10-13，已确认的公共标准。国内完整映射见 [百智 UI](ui-cn.md)，海外见 [EurekaMind UI](ui-global.md)。共同尺寸与状态以本文件为准，市场颜色和字体映射以对应文件为准。UI-TYPE-02 已应用于当前两地 React 界面；其他目标仍按模块渐进改造，用户验收状态单独记录。

## 视觉与主题

国内视觉参考 [百智线上界面](https://100wiser.com/index)，2026-10-12 从渲染 DOM 与 computed CSS 核对。工作台使用白底、浅灰侧栏、深灰主操作；登录、链接与焦点使用亮蓝，品牌装饰使用蓝紫色。海外保留靛蓝色。共同主题在 `src/features/markets/theme.css`，国内组件映射在 `src/features/markets/baizhi-theme.css`；后者仅从国内 layout 导入，所有选择器限定国内市场，覆盖 body 弹窗与下拉浮层，不改模块布局和交互。

| --market-soft | 弱强调背景 | #f2f3f5 | #eef1fc |
| --market-ink | 品牌正文 | #262626 | #253354 |

国内补充 token：`--cn-action: #262626`（工作台主按钮），`--cn-sidebar: #f9f9f9`，`--cn-selected: #ededed`，`--cn-input: #f2f3f5`，`--cn-disabled: #adc6ff`（登录禁用）。保留错误、成功、警告的语义色。控件圆角 6–8px，卡片沿用既有结构；不引入毛玻璃和大面积彩色工作台背景。来源及范围见 [国内视觉对照](../docs/baizhi-visual-reference.md)。

通用正文14px、摘要和筛选12px、页面标题22px、分区标题16px、卡片标题14px。状态／分类／计数等短标签最小11px；可阅读说明与操作标签不低于12px，不用缩小字号解决溢出。间距以 4px 为步长；控件至少 36px 高，移动端主要触控目标至少 44px。完整尺度见下表。

新增组件优先使用语义 token；颜色、尺寸无需复制历史冻结 CSS。`src/features/reference/prototype.css` 为生成文件，禁止直接编辑。主题层优先定义新组件；渐进迁移旧组件，不用全局 `!important` 覆盖交互状态。

## 页面与交互

- 一级分流页使用白色背景，只展示百智（国内版）与 EurekaMind（海外版）两个简洁入口。国内登录只设“个人/团队版”“企业版”两个账号入口；个人与团队不拆分。
- 页面包含明确标题、主操作、筛选／搜索、内容和反馈。空状态解释为什么为空并提供下一步；不要用虚构数据掩盖空状态。
- 主按钮表达具体动作；禁用时说明条件。保存成功必须在持久化成功之后反馈。
- 表单具有可关联 label、格式示例、字段或表单错误反馈。失败保留输入；未保存关闭必须保护。
- 模态弹窗具备语义标题、Esc 关闭、键盘焦点约束和关闭后焦点归还。破坏性操作单独确认。
- 连接器 URL／JSON 添加、编辑、授权、断开、删除复用同一套弹窗行为。
- 市场差异必须有文字标签；不能仅靠颜色表示市场、错误或成功。

## 文案边界

国内会议详情保留现有框架和右侧录音列表，正文、模板控件、评分、转写及图片管理依据百智公开源码与可见交互复刻。个人与团队共用原生组件，权限来自所属工作区。空态插图使用有出处的原站资源，图文摘要只显示实际图片，不绘制替代内容。源码证据、实现范围与服务端依赖见 [会议详情核对](../docs/baizhi-meeting-reference.md)。

产品页面只呈现产品功能、业务规则、必要操作反馈和数据。禁止出现“演示身份”“本地模拟”“待 PM 确认”“场景示意”“不接真实服务”等实现或评审说明。账号隔离说明放在仓库规范。评审身份切换、失败注入等工具默认不显示，仅在显式 `?review=1` 或历史回归入口启用；不要把评审工具当作产品功能。业务资料中谈及客户演示、需求评审属于记录内容，不属于原型说明。下载的账单保留非真实支付凭证标识。

AUTH-UI-04／AUTH-UI-05（2026-10-13，用户确认）：国内登录保留个人／团队版、企业版两张同层级卡片。个人／团队在当前页进入百智登录弹窗；企业卡片导航到 `/cn/enterprise/login/`，按用户第二张截图还原独立游客工作台，并默认显示第三张截图的百销企业专属弹窗。弹窗品牌为现有蓝紫色Logo（28×36px）加“百销 · 企业工作台”，企业代码页标题为“欢迎企业登录”（2026-10-14用户确认）；先企业代码再成员手机号／邮箱，不设个人登录标签、版本切换或侧面宣传区；组织名称和标识保持企业本身。返回导航至 `/cn/?login=1` 的版本选择；企业关闭或 Esc 保留企业游客工作台，账号和私有功能入口可重新唤起企业认证。只展示一个 dialog，短屏内部滚动并保持焦点管理，直接进入时关闭焦点落在可见的企业登录按钮。最大宽520px、内边距40px（窄屏24px），个人表单最大400px；企业代码页主标题24px为截图还原的明确例外。海外保持AUTH-UI-01。此次仅为当前React工程的本地模拟，不跳转或修改100wiser线上站点，账号域保持独立。

## 响应式与无障碍

验收宽度至少 390px、768px、1080px、1440px，桌面重点 1440×900 和 1080×680。正文不得使整页横向溢出；表格可在自身容器滚动。窄屏卡片单列，弹窗不超出可视区且可滚动；侧栏用抽屉，次级详情／Agent 面板按空间收起，不压缩主操作到不可用。桌面主工作台沿用现有导航与内容区布局，不把验收宽度机械当作全部 CSS 断点。

所有操作可用键盘完成；焦点清晰可见；图标按钮有可访问名称；状态消息使用 `role=status`，错误使用 `role=alert`。普通文本对比度目标 4.5:1，识别交互所需的控件边界和状态目标 3:1；装饰分割线不必一律加深。焦点使用清晰实线，不能仅有低对比透明光晕。动效遵循 `prefers-reduced-motion`。

每次 UI 交付提供两地相关页面截图，并核对加载、空、成功、失败、禁用、权限变化及存储失败状态。未确认数值和实现限制记录在市场配置与交付文档中，不进入产品页面。

国内充值引导使用 `credit-recharge-cta` 语义类：亮蓝 #165DFF 背景、白色半粗文字、明确悬停与焦点态。作用于余额卡、个人菜单、团队积分入口与确认充值按钮；不改变其他工作台主按钮。无充值权限的普通成员保留禁用和联系管理员文案。

国内积分入口统一使用轻量蓝紫色额度按钮、白色会员浮层与侧栏引导卡。个人浮层直接显示当前会员身份、升级／管理会员、余额明细、签到、反馈及充值；团队浮层使用同一视觉结构，展示团队身份与共享余额，仅管理员可充值或管理订阅，到期后先续费。任务奖励不出现在团队积分池内。余额、会员状态和任务奖励从当前工作区模型派生，不写死截图中的示例数字。顶部浮层支持键盘、Esc、点击外部关闭及窄屏边界适配。

游客首页两地统一采用轻量内容空态：顶部保留工作区卡片，默认显示“个人工作空间”，点击唤起登录；保留主要导航、会议／闪念、录音、上传和 Agent 入口，正文只显示一处“暂无内容／登录后查看”。不逐模块展示日程、灵感、记账、积分或团队引导；账号入口保留“登录 / 注册”。隐藏入口的私有深链仍按 AUTH-GUEST-01 校验。

登录前后侧栏共用品牌区、工作区卡片与主导航组件；保持相同宽度（展开 272px／收起 76px）、图标、字号、间距与折叠交互。游客卡片副标题显示“Personal · 未登录”，会员身份仅登录后从实际权益派生。

## 组件尺寸目标

落地入口：`src/features/markets/ui-foundations.css` 管理两地语义色、字体和控件尺度；`src/features/reference/market-workbench.css` 负责现有 React 页面与冻结样式的兼容。新组件直接使用基础变量及公共控件，不复制旧页面样式。原生 dialog／popover 同样继承当前市场主题。

两地个人／团队首页概览固定为桌面 280px、窄屏 640px，记录增加时在内部区域滚动；该高度为满足新字号和触控尺寸而从旧版 200／520px 调整。折叠积分入口为 44×44px 图标按钮，保留可访问名称和原操作。移动端国内播放器将进度条放在独立一行。

冻结源中的 `!important`（焦点 outline、四类旧输入的焦点 border／box-shadow、今日待办字号／行高、海外会议模板文字色）在市场作用域内做最小覆盖，并附有代码注释；不扩展为通用 `!important`，不修改冻结／生成源。其他规则使用模块作用域与语义变量。

| 组件 | 参数 |
| --- | --- |
| Button | 紧凑 36px、默认 40px、主要触控 44px；水平 padding 16px |
| IconButton | 桌面至少 36×36px，主要触控至少 44×44px |
| Input／Select | 默认高 40px，登录／触控 44px；水平 padding 12px |
| Textarea | 最小高 96px，多内容内部滚动或按场景扩展 |
| 导航行／菜单项 | 默认高 40px，触控 44px；菜单内边距 8px |
| Tag／Badge | 11／16px，水平 padding 8px；不作为小尺寸点击操作 |
| Dialog | 确认型 400px、标准表单 520px、复杂表单 720px；受视口约束 |
| 登录 Dialog | 容器最大 520px、表单最大 400px；短屏内部滚动 |
| 图标 | 常规 16px、导航 20px、提示 24px，统一线性体系 |
| 圆角 | 按钮国内 6px／海外 8px，输入 8px，卡片 12px，通用弹窗 16px；现有登录 20px 为例外 |

卡片默认无阴影；菜单、浮层使用轻阴影。后续统一的阴影目标：菜单 `0 4px 16px rgba(0,0,0,.08)`，通用弹窗 `0 16px 48px rgba(0,0,0,.16)`，不在本次直接覆盖现有登录样式。动效目标：颜色和悬停 120–160ms，浮层出现 160–220ms；减少动态效果时取消非必要动画。

层级由布局／浮层基础组件集中管理，不在业务页随意增加 z-index。原生 dialog／popover 按浏览器顶层机制处理；菜单属于哪个弹窗、关闭顺序与焦点归还必须明确。

## UI-SELECT-01 · 轻量选择状态

国内／海外共用。区分已选值、鼠标悬停、展开和键盘焦点，不能把 `data-open` 或 `aria-selected` 当作焦点描边条件。

- 鼠标／触控展开：触发器保留原有1px中性边框，箭头翻转；不增加强调色外环或焦点阴影。
- 选中项：浅灰（国内）／浅靛蓝（海外）底色、500字重、右侧16px勾选图标；不描边，不叠加 inset shadow。悬停只改变弱背景，不改变已选值或勾选图标。
- 键盘操作：收起时触发器显示单层2px强调色轮廓、2px偏移，边框仍为中性色；展开后仅当前键盘活动项显示2px内侧轮廓，触发器不同时显示外环。鼠标移动回选项时恢复轻量悬停。
- 选项与勾选图标间距8px，预留图标位置避免切换抖动。浮层1px中性边框，8px圆角，阴影 `0 4px 16px rgba(0,0,0,.08)`。
- 保留方向键、首尾跳转、文字定位、Enter确认、Esc取消、Tab离开与焦点返回。禁用项不触发选择。不能为弱化视觉而全面删除键盘焦点。

实现由公共 `Select` 和两地语义主题负责；业务页不单独覆盖选中边框。覆盖闪念排序、设置、会议和弹窗中的复用控件，验证鼠标、触控、键盘及两地390/1440px。

## 状态与语义色目标

| 状态 | 文字／图标 | 弱背景 |
| --- | --- | --- |
| 成功 | #16803C | #F0FDF4 |
| 警告 | #B45309 | #FFFBEB |
| 错误／危险 | #CF313B | #FFF1F2 |
| 信息 | 当前市场强调色 | 当前市场弱强调背景 |

这些是确认后的共用目标，旧模块状态色逐步收敛。每个组合检查实际背景对比度；状态必须附带文字或图标。

| 状态 | 行为契约 |
| --- | --- |
| 默认／悬停／按下 | 稳定反馈，不引起布局跳动 |
| 焦点 | 键盘可见，不能仅改变细微底色；关闭浮层返回触发点 |
| 加载 | 保持按钮宽度、防重复提交，未知进度不显示虚假百分比 |
| 成功 | 持久化／真实业务完成信号之后反馈 |
| 错误 | 原因与恢复动作，保留输入 |
| 禁用 | 提供原因，不只降低透明度 |
| 无权限／只读 | 根据模型派生，说明下一步；不可只靠隐藏按钮实施授权 |
| 空 | 区分无数据、无搜索结果、无访问权限；不虚构内容填充 |

对比度依据：[W3C 普通文字](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字控件](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

国内首页简报待办为 12/18px（2026-10-13 用户确认），保留点击区域；海外仍为 14/22px。国内企业独立登录页尺寸以 docs/auth-flows.md 的线上核对为场景例外。

### UI-FOCUS-02 · 输入与卡片状态

国内／海外文本输入框（包含自动聚焦的登录表单）使用单层1px强调色内侧实线，offset -1px，不叠加强调色边框、外环或光晕。带前缀图标的复合输入在整个容器上显示这条线，子输入不重复描边。复选框、按钮及其他控件保留单层2px键盘焦点；Select沿用UI-SELECT-01。错误反馈及键盘可操作性保持不变。

国内积分套餐、订阅周期、加时包使用1px中性边框、浅灰选中底和勾选标记；选择状态不叠加阴影描边，键盘焦点独立显示。

### UI-TYPE-02 · 全局文字层级补充（2026-10-13）

公共语义字号由 `ui-foundations.css` 定义，当前 React 界面通过 `market-workbench.css` 与 `market-typography.css` 映射，body浮层同样继承。一级页面22/30px、二级分区16/24px、三级卡片14/22px，标题600字重；首页欢迎和认证24/32px，弹窗标题18/26px、内部依次16/24与14/22。顶部工作区名称16/24px，低于内容页主标题。HTML heading层级不直接决定视觉字号，按所属内容角色映射。

导航13/20px；正文、表单及主要按钮14px；客户卡片摘要、次要描述、筛选标签／值／下拉选项12/18px；时间与来源12/18px；状态、分类、计数短标签11/16px。11px不用于段落、表单或操作名称。缩小字号不缩小40px桌面／44px移动点击区域，长篇会议与Agent阅读内容维持15px，富文本用户格式不覆盖。
