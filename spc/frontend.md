# 前端研发规范

版本：1.1 / 2026-10-13。已由产品负责人确认。适用于 PM、研发和 AI 编程工具的后续迭代；本次落地规范与检查，不代表历史页面已全部改造。

## 工程与交付

| 规则 ID | 要求 |
| --- | --- |
| FE-01 | 沿用 Next.js App Router、React、TypeScript strict；新增业务组件用 TSX，模型和工具用 TS。当前 package.json 为版本依据，升级单独评审。 |
| FE-02 | PM 可操作原型必须进入现有 React 工程，通过 `/cn/`、`/global/` 及其产品路由访问。 |
| FE-03 | 禁止新增手写 HTML 产品页、业务 iframe、HTML 字符串拼接页面和全局脚本管理业务状态。 |
| FE-04 | 保留静态导出和两地打包。`out/`、`public/prototype/`、静态包是生成产物，不能作为编辑源。 |
| FE-06 | 冻结历史原型不承接新业务；禁止手改生成的 `prototype.css` 或通过修改冻结源来适配新规则。 |
| FE-07 | 基础 UI 不依赖业务模块；通过类型明确的 Props 和回调协作，不操作其他模块 DOM。 |
| FE-08 | 业务存储和跳转使用现有市场适配；保持 MARKET-01、ACCOUNT-01、ENTERPRISE-01、ASYNC-01。 |
| FE-09 | 样式使用语义变量与模块作用域，公共组件变更验证两地及浮层主题。 |
| FE-10 | 每轮交付包含组件复用、市场影响、状态和验证证据；不能以单文件演示替代工程交付。 |

现行规则保留编号空缺，不重新编号。

Next.js 构建生成 HTML 属于正常部署形式；限制的是手工维护的产品页面。可保留已登记的历史文档页面、冻结原型和说明页。用户下载的报告 HTML 属于导出内容，不能承担产品页面逻辑。新说明材料优先 Markdown；确需新增 HTML 文档须登记具体文件及用途并评审，不得用目录级豁免绕过 FE-03。

富文本和 Markdown 是内容渲染例外：仅在登记的内容边界使用，输入和展示前按契约清洗，不允许嵌入业务事件、脚本或页面逻辑。现有编辑器 DOM 读写、撤销快照不等于允许其他模块直接写 HTML。静态检查不替代清洗器安全测试。

## 分层与依赖

| 层 | 职责 | 边界 |
| --- | --- | --- |
| `src/app` | 路由、layout、元信息、组装模块入口 | 不堆积表单、计费、权限实现 |
| `src/features/<module>` | 业务页面、组件、Hooks、业务动作 | 不复制另一市场的完整模块，不访问其他模块私有实现 |
| 模块内 model／store | 数据类型、校验、状态转换、持久化适配 | 不依赖 JSX 或页面 DOM；富文本清洗为登记例外 |
| `src/components/ui` | 无业务知识的按钮、输入、弹窗、菜单、表格 | 不导入业务模型，不维护账号、余额或权限 |
| `src/lib` | 路由等跨模块技术能力 | 不成为业务逻辑杂物箱；不能经此绕过 UI 依赖限制 |
| `src/features/markets` | 配置、身份域、存储、主题、市场入口 | 市场不是语言或工作区 |

数据流：路由 → 业务页面 → Hook／业务动作 → 模型与数据适配；业务页面 → 业务组件 → 基础 UI。

新模块按需设置 `components/`、`hooks/`、`model/` 和模块入口，不强制给小模块创建空目录。跨模块能力通过明确导出接口复用，避免循环依赖。沿用已有结构，随需求逐步整理，不一次性搬迁全部工程。

## 组件和状态

- 页面负责组合与流程协调；复杂表单、列表项、工具栏、详情分区、弹窗分别实现。
- 校验、权限与状态转换集中到模型／业务动作，避免散落 JSX。保存前重检权限和快照；写入成功后才报告成功。
- 单文件超过约 300 行评估拆分，超过 500 行在评审说明职责；这是人工评审提示，不按行数机械拆分。
- 出现稳定复用后再抽公共组件。不要为减少几行代码创建过度泛化的组件。
- Props 明确类型；禁止用 any 绕过契约。基础组件只接收展示值、状态与回调。
- Client Component 只放必要交互边界；保留重型模块动态加载。派生值直接计算，不用 Effect 同步第二份状态。
- 沿用现有 Hooks、模型与适配层；新增全局状态、表单或 UI 框架须说明既有能力无法满足的原因。
- `Modal` 与 `ReferenceDialog` 暂时兼容，后续收敛同一行为底座；新模块不再增加第三套焦点、关闭或遮罩机制。
- 字段、菜单、异步操作覆盖加载、空、成功、失败、禁用、无权限、只读及恢复状态。

公共控件现状与待收敛契约见 [组件规范](components.md)，视觉参数见 [公共 UI](ui.md)。

## 两地与数据

颜色和视觉差异放主题；价格、额度、渠道、目录放市场配置；真实流程差异用独立业务组件并复用基础 UI。禁止复制完整国内／海外工程，禁止在基础按钮中判断账户或订阅。

业务调用 `marketStorage`／`marketSessionStorage`、`appUrl`／`marketUrl`。纯模型接收 Storage 接口。异步动作锁定发起时市场、账号、工作区和稳定操作 ID，重试不能改变归属。不得自动迁移或清空旧数据。前端模拟隔离不能替代服务端授权。

## 样式职责

基础值（颜色／字号／间距）→ 语义变量（正文／主操作／边框／危险）→ 组件变量（高度／圆角／宽度）。国内和海外共享语义名称，主题负责赋值，见 [国内 UI](ui-cn.md) 和 [海外 UI](ui-global.md)。

- 新独立组件优先 CSS Modules；现有模块 CSS 继续维护，但选择器限定模块范围。
- Tailwind 用于布局和组合；同一组件核心样式不要在多个系统中重复定义。
- 内联样式仅用于动态宽度、进度、坐标等运行时值。
- 新组件不能重复硬编码品牌色；不新增无作用域的 button、input、.primary 等全局覆盖。
- 不用不断追加 `!important` 解决主题冲突；遗留例外须说明来源和退出条件。
- 主题必须覆盖 body 上的 dialog／popover；组件不能通过复制另一主题 CSS 实现市场切换。

## 自动门槛与人工评审

`npm run check:architecture` 使用 TypeScript AST 和精确例外登记，随 `npm run check:spc` 进入已有 CI。登记文件为 `architecture-policy.json`，不能为了消除失败自动更新登记。

| 检查 | 范围／处理 |
| --- | --- |
| HTML 文件 | Git 可见的已跟踪和未忽略文件，只有逐文件登记的 HTML 可以存在；构建产物不作为开发源 |
| 冻结源和生成样式 | 校验冻结树及 prototype.css／symbols.tsx 指纹；变更须单独说明历史基线维护原因 |
| iframe | 扫描 src 下当前应用源码中的 JSX 标签和字面量元素创建调用 |
| 原生存储 | 扫描当前源码中的标识符和静态属性访问；仅市场存储适配文件豁免 |
| HTML 写入 | 未登记的 innerHTML／outerHTML 赋值、dangerouslySetInnerHTML、insertAdjacentHTML、document.write 被拒绝 |
| UI 依赖 | 检查基础 UI 到业务层／路由层的直接和可解析的本地间接导入；历史单条依赖登记兼容 |
| 新业务 JavaScript | 仅登记的历史 JS 模型保留；新增业务使用 TS／TSX |

静态检查覆盖常见直接语法，不能证明任意动态反射、运行时生成代码或富文本绝对安全。新增检查例外必须注明具体位置、原因、主责角色和退出条件；不能用整个业务目录豁免。既有历史说明 HTML 不得改造为产品入口。

人工评审仍负责：业务合理性、模块私有边界、复杂度、品牌色硬编码、全局选择器、组件复用、截图与交互质量。这些不因自动检查通过而视为完成。

## 验证与实施状态

- 检查脚本变更：架构检查自身的正反例测试、SPC、lint／类型及构建；不因仅修改文档而宣称完成 UI 验收。
- 产品变更：`npm run check`、`npm run build` 和受影响测试。公共组件、主题或隔离规则变更须跑两地关键链路。
- 主题验收覆盖登录、游客／登录后工作台、弹窗／菜单、移动端；业务基线优先于被替代的旧测试。
- 第一阶段：规范、PM 模板、架构门槛。第二阶段：主题变量、基础组件契约与 React 状态展示页。第三阶段：按模块拆分大文件、收敛旧样式和历史依赖。
- 当前确认不等于已完成第二、三阶段；不自动发布，不改变现有价格、权限、账号与存储行为。
