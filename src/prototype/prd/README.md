## 站点与源文件

`content.json` 是唯一发布内容源。本目录是已登记的文档站点，由 `prepare-prototype.mjs` 复制，访问 `/prototype/prd/index.html`；不是独立产品原型，不用于实现业务功能。国内／海外业务分别通过 `/cn/`、`/global/` 访问。

schemaVersion=1、documentId 固定。每章包含稳定 id、title、group、summary、body 和纯文本 reviewNotes；正文支持标题、表格、列表、粗体、行内代码、本目录 images 图片与 flow 图。正文不执行 HTML；普通 Markdown 链接目前不渲染为链接，章节跳转通过目录及“链接”按钮使用。

每次发布更新 revision。版本、日期、原型依据和参考状态须同步；`prototypeCommit` 记录所核对的业务源码，不把新文档提交当作真实服务发布。

## 编辑、备份和发布

1. 网页章节“编辑”只修改当前浏览器工作稿；保存前可导出 JSON 备份，导出 Markdown 用于阅读。
2. 导入仅接受与当前发布版兼容的章节结构；先预览再确认，不修改仓库发布版。
3. 本版在顶部协作模块外增加 13 个市场专项章节。旧 36／38 章工作稿需按稳定 ID 在仓库合并结构；旧草稿不会自动迁移或删除。看到不兼容提示时，先由维护者备份浏览器中的 `eureka:prd:draft:v1` 原始值，再合并；不要把页面导出的当前发布版误当作已恢复的旧草稿。
4. 网页发布面板只生成 payload 与 GitHub 操作指引；提交或 PR 合入 `develop` 并经 CI／Pages 成功后，全员才可见。复制内容或打开 GitHub 不代表发布成功。
5. 发布后核对线上 revision、国内／海外原型入口和文档锚点。浏览器旧稿提示更新时，人工逐章合并并确认新基线。

未授权的新内容不自动发布。回滚内容与模块清单不涉及业务数据回滚；不清空用户浏览器资料。

## 图片与流程

图片 Markdown 放在对应规则小节下。`reader.js` 转为“查看界面”入口：大屏右侧对照，小屏模态抽屉，支持切图、原图、定位、Escape；打印展开。新增截图来自当前工程，不能用旧图片证明新交互完成。

显式刷新配图时才执行：

```sh
npm run build
PRD_ILLUSTRATIONS=1 PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- tests/e2e/prd-illustrations.spec.ts --workers=1
npm run build
```

按受影响测试及 `-g` 限定截图范围；不要盲目覆盖全部旧图。参考 PDF 不复制进公共站点。

flow 围栏中使用 JSON，包含 title、nodes、edges；节点使用唯一 id、label、x/y 和可选 kind（start／step／decision／end／error）。最多 40 节点、60 边，x/y 0–10；文字按数据转义，非法 JSON 有错误反馈。大屏图宽不超过 620px，窄屏内部滚动，打印为 SVG。

## 验证与边界

- 结构：JSON 可解析、章节 ID 唯一、模块来源／依赖／规则存在、验收引用有定义。
- 文档交互：目录、搜索、编辑保存、JSON／Markdown 导出、导入、旧草稿不覆盖、图示及打印。
- 布局：桌面与手机，无整页横向溢出，宽矩阵在表格内部滚动。
- 运行 `npm run check` 和 `npm run build`；仅文档与元数据调整不宣称重新完成真实产品或服务验收。
- 历史 PRD 测试中硬编码 V1.3／35 章／旧编号的断言不能作为当前内容标准；应按当前版本、稳定锚点和实际功能核对，不能为旧断言恢复过期规则。
