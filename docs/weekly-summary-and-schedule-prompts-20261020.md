# 周度会议总结、日程三阶段提示词及关联会议密度

2026-10-20，当前分支 `codex/quick-schedule-tasks`，国内／海外同步。延续此前未提交实现；未合入或发布。负责人沿用佳音（闪念日程）、关联 UI／Agent 与会议模块按现有分工联合评审，本地自动化不表示人工签署。

## 用户确认的统计周期

周总结默认展示**上一完整自然周，周一至周日，每周一更新一期**。例如 2026-10-20 显示 2026-10-12 00:00 至 2026-10-19 00:00 之前的记录；10月19日的会议属于下一期。区间为左闭右开，使用设备本地时区的日历日计算，不使用滚动7天或固定168小时计算。

页面每分钟及重新聚焦时检查周边界，周一切换到刚结束的完整周；再次打开也按当前日期计算。当前周选择只提供最近8个**已结束**自然周，不混入本周未结束的记录。周内原始资料或权限变化会反映在对应统计周，不保存一份脱离权限的永久摘要快照，不创建本机或远端定时任务。

## 首页与详情设计

- 仅团队首页展示“周度会议总结”，标题旁显示统计日期和上周／历史周标记；个人首页不展示该模块。团队周总结沿用当前身份可见记录。
- 周总结 Agent 请求将当前完整自然周内所有有权访问会议的 ID 一并附带，并要求读取每条会议标题、总结和转写，按实际内容跨会议归并议题后返回标题、摘要和来源 ID；不使用固定通用分类。输出限定在已附 ID，并经过结构校验，避免跨周或越权来源进入结果。
- Agent 输入框只预填简洁、可读的问题；周期、授权会议 ID、生成指令和 JSON 输出结构作为独立的结构化请求随 Agent 调用传递，不把 Schema 或内部格式要求拼进用户问题。
- 当前 React 本地演示层仍用会议标题和保存摘要构造即时回退预览；真实语义提取接入以 `buildWeeklySummaryGenerationRequest` 的周期、来源 ID、`instructions` 和 `outputSchema` 字段为契约，由 Agent 服务实现后供周总结模块展示。
- 概览每项显示动态议题标题、会议数量和摘要，不提供重复的逐项“查看详情”；模块统一提供一个“查看详情”和一个“基于本周总结问 Agent”入口。无摘要时说明记录不足。
- 桌面保留280px、窄屏640px的既有概览高度，内部滚动；使用模块底部唯一的“查看详情”入口打开包含全部议题的详情。
- 详情复用 ReferenceDialog：桌面最大920px，短屏内容区滚动，标题与底部操作固定；390px布局自适应。顶部展示完整统计日期、会议数和创建人数，提供统计周选择与全部／类型切换。
- 详情内容依次为议题摘要、会议依据、已记录要点及后续关注。会议依据显示原始标题入口、录音时间／来源／创建人、摘要；长文可展开。结构化要点必须能在已保存总结或转写中逐字找到，未命中的观察不展示为事实。
- “基于本周总结问 Agent”直接打开右侧 Agent，输入框预填简洁问题，并以独立请求附带统计周期指令和该周会议 ID；个人首页将个人可读会议摘要作为 Agent 上下文。详情内继续提问也沿用此入口。发送沿用现有权限、用量与会话服务，不将其他周文件默认并入。

数据只来自当前 `M.visible(workspace, actor)` 的会议记录，过滤删除记录及联系人／笔记快照；按稳定ID去重。单次记录不会自动升级为跨会议共识。普通成员不会通过周总结获得私有会议标题或摘要，团队到期时禁止打开总结详情；原始会议权限保持现有规则。

## 日程前、中、后

提示词已按用户本次提供的三段精简文本逐字更新，保留原文分段、编号和重点标记；模板保存在 `src/features/personal/schedule-prompts.ts`，所有创建来源共用。

| 场景 | 按钮（用户指定） | 助理角色与任务 |
| --- | --- | --- |
| 日程前 | 准备这场日程 | 个人日程准备助理：识别对象和主题、检索历史交集、按能力补充公开资料、形成准备材料并提炼3～5个准备要点 |
| 日程中 | 查看相关上下文 | 日程上下文助理：快速呈现背景、历史结论、承诺、风险、待办与原始入口，不重复完整会前报告，不假设已有本次录音或总结 |
| 日程后 | 回顾这场日程 | 日程复盘与后续跟进助理：优先取得本次实际记录、还原结果、比对历史变化，并按行动事项／责任人／截止时间／关联结论／来源／状态整理建议；缺失标记待确认 |

三段提示词正文不再重复附加日程字段，输入框严格展示用户指定的精简文案。日程标题、起止时间、地点、参与人、我的备注、关联会议ID及来源属性仍通过已有 ScheduleContext 的 record 附带；实体线索和有权访问且未删除的相关资产也继续附带并在 Agent 中展示。时间无效或取消日程的保守提示词保持原样。

信息缺失、同名歧义或未检索到记录时明确说明材料限制；无结果不等于交集不存在。日程结束不代表已发生沟通或已达成结论。默认只提供分析与建议，不自动创建／修改／关闭待办或发送消息。联网检索仍受现有工程能力限制，未获取网页时不伪造结果；本轮更新提示词，不新增真实外部Agent服务。

原日程阶段的入口位置、时间边界、未保存草稿保护与只读规则保持此前实现。时间无效或已取消仍使用“梳理这次日程”的保守入口，不强行归入前／中／后。

## 关联会议屏效

关联会议弹窗与已关联会议卡均将“会议创建人”并入同一个元信息元素：

`录音时间 · 录音来源 · 会议创建人：姓名`

常规宽度不单独占行，窄屏可自然换行，不用强制单行造成溢出。弹窗继续不展示总结；个人版不增加创建人字段。

新增纯模型 `spaces/model/weekly-summary.ts`，将周范围、类型分类、去重、证据校验与展示组件分开；新增 `spaces/weekly-summary.tsx` 及 CSS Modules。沿用现有两地主题、ReferenceDialog、Select、工作区权限、Agent上下文和静态导出；未修改冻结原型或生成样式。
