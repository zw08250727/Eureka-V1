# 日程编辑布局与会中上下文入口设计

**状态：** 已获用户确认（选择 A：两列对齐）
**范围：** 国内版与海外版；个人空间与团队空间
**基线：** `develop` 当前合并结果；本次工作分支为 `codex/calendar-layout-context`

## 问题与目标

日程编辑弹窗中，地点与参与人控件的内部结构不同，导致输入框错位；团队成员选择和说明挤在参与人列，说明文案还会被窄列异常折行。日程进行中，“查看相关上下文”入口当前位于详情顶部操作区，与会后入口的位置不一致。

目标是在不改动保存、权限、共享及 Agent 数据行为的前提下，统一编辑表单的视觉节奏，并让会中入口与会后入口占据同一详情位置。国内／海外复用同一结构，主题色继续由市场主题提供。

## 方案

### 日程编辑弹窗：两列对齐

采用用户选择的 A 方案，按信息关系组织字段：

1. 标题占满整行。
2. 开始时间与结束时间并列。
3. 提醒时间控件独占一行；时区和待办截止时间说明另占一条全宽说明行，使用可读的辅助文字样式并按弹窗可用宽度自然换行。
4. 地点与手动填写的参与人输入框并列，字段标签和输入框顶部对齐。
5. 团队空间中的团队成员选择器移到下一条全宽行，提示文案位于选择器下方并占满可用宽度；个人空间不显示此团队专属区域。
6. 我的备注占满整行。

窄视口沿用弹窗现有响应式边界，将两列字段堆叠为单列；不得产生横向溢出。待办编辑沿用相同的全宽说明行规则，但不显示日程专属地点／参与人字段。

### 会中上下文入口

将进行中日程的“查看相关上下文”从详情顶部操作区移到 `ScheduleAssistEntry` 的详情内容位置，与会后“回顾这场日程”卡片完全对齐。继续使用当前阶段对应的标题、说明和按钮文案，并调用现有 `prepareSchedule` 流程打开 Agent。保持只读禁用、加载防重复提交和会前／会后入口行为不变。

### 主题与组件边界

日程编辑器和详情页是国内／海外共用的业务组件；本次只调整该组件的布局与入口编排，不复制市场组件，不改主题 token。国内保留黑灰／亮蓝映射，海外保留靛蓝映射。个人／团队差异仅用于是否呈现团队成员选择器，不改变权限或共享模型。

## 状态与兼容性

- 必填校验、错误保留输入、保存成功反馈、未保存关闭保护保持现状。
- 只读状态仍禁用编辑和 Agent 操作；Agent 忙碌时继续显示现有加载文案并阻止重复触发。
- 参会人手动填写与团队成员选择的共享确认、成员撤权提示及访问权限保持原有业务规则。
- 日程阶段判断、默认提示词、Agent 会话上下文及资产检索不在本次修改范围。
- 不改持久化结构、市场存储、路由或远端发布状态。

## 文件与测试范围

- `src/features/personal/calendar-dialogs.tsx`：整理表单字段的语义分组与全宽说明布局。
- 新增 `src/features/personal/calendar-dialogs.module.css`：仅为日程编辑字段组提供布局样式，避免修改生成的 `src/features/reference/prototype.css` 或增加全局选择器；保留 `calendar-participants.module.css` 的现有参与人控件职责。
- `src/features/personal/calendar.tsx`：将进行中日程入口放到与会后入口相同的详情内容插槽，移除顶部重复入口。
- `tests/e2e/schedule-assist-guide.spec.ts`、`tests/e2e/personal-actions.spec.ts`、`tests/e2e/team-schedule-refinements.spec.ts`：验证真实 React 路由下的两地阶段入口、Agent 调用回归、个人／团队编辑布局与共享规则。

实现前先检查上述样式实际归属；若布局规则位于其他模块 CSS，则修改真正负责该组件的文件，不为凑合路径新增重复样式。

## 验收标准

1. 国内／海外个人日程编辑中，地点与手动参与人输入同排、同一纵向起点；团队编辑中团队成员选择器另起全宽行，辅助说明可自然换行。
2. 待办和日程的时间说明不会被挤入相邻窄列；390px、768px、1080px、1440px 下弹窗无横向溢出。
3. 国内／海外团队的团队成员选择区域保持可用，个人空间不出现该区域。
4. 进行中日程的“查看相关上下文”出现在会后入口原位置，不再占据详情顶部操作区；触发后仍带入当前日程并按会中阶段进入 Agent。
5. 会前“准备这场日程”、会后“回顾这场日程”、只读／忙碌状态以及共享确认、撤权行为均不回归。
6. 完成受影响的国内／海外日历 E2E 用例，并运行仓库要求的 `npm run check` 与 `npm run build`。

## 备选方案

备选 B 是把编辑表单全部改成单列。它最容易保持对称，但桌面弹窗会明显增高并增加滚动。用户已选择 A：桌面使用紧凑双列结构，并以全宽团队成员行和全宽说明行消除错位；窄屏再退化为单列。
